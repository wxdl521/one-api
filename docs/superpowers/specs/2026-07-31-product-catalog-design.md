# 商品目录与管理员上架设计

## 目标

提供独立的商品目录和商品详情页，让管理员无需修改订阅计费配置即可上架通用商品。测试版仅实现商品展示和管理，不新增订单、在线支付、库存或自动/人工发货工作流。

## 范围

- 登录用户可浏览已上架商品，并打开商品详情页。
- 管理员可创建、编辑、上架或下架商品。
- 商品可为 `manual`（人工发货，如 CDK）或 `subscription`（关联一个现有订阅套餐）。
- 商品保存封面 URL、名称、简短卖点、详细说明、类型、排序、上架状态和可选的订阅套餐 ID。
- 商品详情页为测试版展示页：人工发货商品显示“联系管理员购买”；订阅商品显示“前往订阅管理”入口，复用现有订阅配置但不在本次增加新支付调用。

## 非目标

- 不创建通用订单、支付、库存、CDK 导入、发货、退款或评价功能。
- 不改变既有的 SubscriptionPlan、SubscriptionOrder 或兑换码业务逻辑。
- 不上传或托管图片；管理员填写自己托管的封面图片 URL。

## 架构

新增 `Product` 模型，由 `product_type` 区分 `manual` 和 `subscription`。当类型为 `subscription` 时，`subscription_plan_id` 必填并指向现有套餐；`manual` 类型不绑定套餐。服务端分别提供已登录用户可读取的已上架商品接口和管理员 CRUD 接口，所有写操作沿用管理员认证。

前端增加独立 `products` feature：用户目录页、详情页及管理员商品管理页均通过 React Query 调用新 API。商品管理使用表格和表单抽屉；商品展示使用卡片列表。路由在登录区域内，以 `/products` 和 `/products/$productId` 提供用户视图，并以 `/products/manage` 提供管理员视图。

## 数据与校验

`Product` 使用跨数据库兼容字段：`varchar` 存储短文本与 URL，`text` 存储详情，整型保存排序与时间。服务端对名称、卖点、图片 URL、详情长度和类型做校验；订阅商品必须绑定存在的套餐。已下架商品不会出现在用户接口中，但管理员仍可查看和编辑。

## 错误处理与测试

服务端测试覆盖：管理员可创建人工发货商品、订阅商品缺少套餐被拒绝、普通用户只能读取上架商品、下架商品不出现在用户列表。前端测试覆盖商品类型表单校验和详情页的购买指引。所有新增 UI 文案使用现有 i18n 机制。

## 验收标准

管理员可以填写封面 URL、商品信息和类型并上架商品；登录用户在商品目录看到上架商品，打开独立详情页查看说明；管理员下架后，该商品立即从用户目录消失。
