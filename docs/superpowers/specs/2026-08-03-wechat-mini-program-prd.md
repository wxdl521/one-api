# 微信小程序用户服务端改造 PRD

**状态：** 已确认

**版本：** 1.0

**日期：** 2026-08-03

**目标产品：** The One 微信小程序（首期）

## 1. 背景与问题

The One 已具备 AI 网关、用户/Token、额度、套餐、订单、用量和异步任务能力，但现有前端是面向桌面浏览器的完整控制台。普通用户在移动端查看额度、管理一枚日常使用的 Token、进行模型连通性测试或查看订单，必须打开复杂的 Web 控制台；管理员能力、上游渠道和计费规则又不适合向小程序暴露。

首期将小程序定位为“用户服务端”，而不是完整后台，也不是面向公众的通用 AI 消费应用。它让已注册用户和微信新用户在微信内完成低风险的自助服务，并保持现有 Web 控制台为唯一的管理端和完整支付端。

## 2. 产品目标

### 2.1 用户目标

1. 用户可用微信身份安全进入或绑定 The One 账号。
2. 用户可在 3 次点击内看到当前额度、套餐状态和近期用量。
3. 用户可创建、查看和撤销仅属于小程序的受限 API Token；完整 Token 只在创建成功时显示一次。
4. 用户可从小程序发起一次受限的文本模型连通性测试，且复用现有鉴权、模型可用性、预扣费和结算链路。
5. 用户可查看套餐、商品和已有订单，并安全跳转到现有 Web 支付页完成支付。

### 2.2 业务目标与衡量标准

| 指标 | 首期标准 |
| --- | --- |
| 自助覆盖 | 登录/绑定、额度、用量、套餐、订单、Token、文本测试均可在小程序完成或安全跳转完成 |
| 安全边界 | 小程序接口不返回上游 Key、管理员数据、既有 Web Token 明文或刷新 Cookie |
| Token 管理 | 小程序只能操作 `source=miniapp` 的 Token；任何 Token 明文只在创建响应中出现一次 |
| 核心可用性 | 除模型上游调用外，P95 API 响应不高于 1 秒；账户首页不高于 2 秒 |
| 计费一致性 | 文本测试 100% 进入现有预算、预扣费、结算和消费日志链路，不新增独立钱包或旁路扣费 |
| 发布门槛 | SQLite、MySQL、PostgreSQL 均完成迁移与核心回归；微信登录、Token 隔离和扣费回归通过 |

## 3. 已确认的产品决策

| 决策项 | 结论 |
| --- | --- |
| 产品定位 | 用户服务端，不制作完整管理后台 |
| 技术路线 | 独立小程序前端 + 专属 `/api/miniapp/v1` Go BFF；不直接调用现有通用 `/api` 或 `/v1` 接口 |
| 前端 | 独立 `miniapp/` 工程，Taro + React + TypeScript；仅共享纯 TypeScript 类型、请求契约和业务规则，不共享浏览器 UI 组件 |
| 首期能力 | 账户服务、受限文本测试、小程序专属 Token、套餐/订单展示和 Web 支付跳转 |
| 首次登录 | 用户可创建新账号或绑定已有 The One 账号 |
| 支付 | 小程序不接入微信支付；只进入经服务端校验的同源 Web 支付页 |
| Token 范围 | 只管理由小程序创建的受限 Token；不展示、修改或撤销既有 Token |
| AI 能力 | 仅文本对话/连通性测试；不支持图片、文件、语音、工具调用、异步任务或自由模型参数 |

## 4. 用户与权限

### 4.1 用户角色

- **普通用户：** 已有 The One 账号，查看资产、创建受限 Token、测试文字模型、查看订单。
- **微信新用户：** 首次使用小程序，按站点注册策略创建普通账号后使用同等能力。
- **管理员：** 不在小程序获得特殊入口；仍在 Web 控制台管理渠道、用户、全局定价、商品和支付配置。

### 4.2 权限原则

1. Mini BFF 只接收已认证的用户会话或微信登录 code，所有资源按当前用户 ID 过滤。
2. BFF 不代理管理员接口，也不把“前端隐藏”当作权限控制。
3. 每个文本测试模型必须同时满足：小程序全局白名单、用户所属组可用、用户 Token/套餐限制允许、当前有可用渠道。
4. Token 只能在所有权和 `source=miniapp` 同时匹配时被读取、更新状态或撤销。
5. 用户已被禁用、额度不足、套餐/模型无权访问时，BFF 在调用 Relay 前返回明确业务错误。

## 5. 信息架构与页面

小程序采用四个底部页签，未登录状态只展示登录/绑定页。

| 页签/页面 | 用户任务 | P0 内容 |
| --- | --- | --- |
| 首页 | 快速理解账户状态 | 可用额度、当前套餐、近期用量、最近订单、快捷入口、到期/额度不足提醒 |
| 服务 | 查看可购买服务并完成测试 | 套餐/商品列表、详情、文本测试入口、受限模型选择 |
| Token | 管理小程序创建的 Token | 列表、创建、一次性密钥展示、启停、撤销、空状态说明 |
| 我的 | 管理身份与账户 | 昵称/头像展示、绑定状态、会话退出、跳转 Web 账户与支付页、隐私说明 |

页面所有用户可见文案必须通过小程序 i18n 资源管理；首期提供简体中文，结构上保留与现有前端相同的英文源键扩展能力。

## 6. 核心用户流程

### 6.1 微信登录、创建与绑定

1. 用户打开小程序，前端调用 `wx.login` 获取一次性 `code`。
2. 前端向 `POST /api/miniapp/v1/auth/wechat` 发送 `code`；后端在服务端调用微信 `code2Session`，绝不将 AppSecret、session_key 或上游密钥下发给小程序。
3. 后端以 `(app_id, open_id)` 查询小程序身份映射：
   - 已映射且用户启用：签发/续发小程序会话，进入首页；
   - 未映射：返回“创建新账号”与“绑定已有账号”两种下一步；
   - 已映射但用户已禁用：拒绝登录，不暴露用户资料。
4. 用户选择创建账号时，后端仅在现有站点允许注册的前提下创建普通用户、创建身份映射并签发会话；注册关闭时只允许绑定已有账号。
5. 用户选择绑定已有账号时，BFF 创建一个 5 分钟有效、一次性、不可猜测的绑定流程，展示已验证的同源 Web 绑定页入口。用户在 Web 页复用现有密码、OAuth、Passkey 和 2FA 登录能力确认绑定；Web 端在同一数据库事务内消费流程并写入身份映射。
6. 小程序轮询绑定状态；成功后重新调用微信登录接口以获得小程序会话。已绑定到其他用户的微信身份必须原子性拒绝，不能覆盖或合并账号。

绑定流程必须复用 `auth_flows` 的 HMAC 令牌、过期和一次性消费机制，新增独立 purpose `miniapp_bind`；其 payload 只保存身份记录 ID 与必要的状态，不保存 OpenID、code、密码、浏览器 Cookie 或 Token 明文。

### 6.2 小程序会话

1. 登录成功后返回短期 Bearer access token、会话 ID、过期时间和脱敏用户摘要；前端仅保存 access token 和会话 ID。
2. access token 即将到期时，前端再次调用 `wx.login`，以新 code 和会话 ID 请求 `POST /auth/renew`。服务端验证 code 对应的 OpenID 与该会话的身份映射一致后，对同一有效会话重新签发 access token；不创建新用户会话，不使用浏览器刷新 Cookie。
3. 登录会话标识为 `wechat-miniapp`，进入现有会话审计和撤销体系。用户在小程序退出时撤销该会话并清除本地 access token；用户在 Web 端撤销会话或被禁用后，小程序下一次请求必须失效。
4. access token 有效期不超过 30 分钟。小程序不保存刷新 Token、AppSecret、微信 session_key 或任何上游凭证。

### 6.3 首页与账户服务

首页返回经过 BFF 聚合和脱敏的账户摘要：显示名、额度、当前有效套餐、近 30 天用量汇总、最近 5 条消费记录和最近 3 个订单。金额/额度沿用站点现有显示与换算规则，不能由小程序自行计算计费结果。

点击套餐或商品进入详情。点击“前往支付”时，BFF 只返回配置域名下、路径白名单内的 Web URL；不携带用户 ID、access token、支付参数或任意外部跳转地址。用户在该 Web 页面按既有登录与支付流程完成操作，返回小程序后由订单列表刷新状态。首期不在小程序内创建支付订单、调用微信支付或处理支付回调。

### 6.4 小程序专属 Token

#### 列表

列表仅返回当前用户 `source=miniapp` 的 Token：名称、脱敏前缀/后缀、状态、创建/最近使用/到期时间、分组和模型限制摘要。列表不提供复制明文、查看密钥、编辑 IP 白名单、跨组重试、无限有效期或配额分配。

#### 创建

用户填写名称，选择允许的用户分组和模型，选择固定有效期（7、30 或 90 天，默认 30 天）。BFF 服务端强制校验：

- 名称去空格后长度为 1–50；
- 分组为当前用户可用分组；
- 模型集合非空、无重复，且均同时在用户可用模型和小程序模型白名单中；
- 令牌数不超过现有 `MaxUserTokens`；
- Token 固定为 `ModelLimitsEnabled=true`、`CrossGroupRetry=false`、`UnlimitedQuota=true`、`source=miniapp`。其中 `UnlimitedQuota=true` 仅关闭单 Token 子配额，实际请求仍受用户账户额度与套餐约束；BFF 不接受客户端传入的配额、IP 白名单、无限有效期或任意原始模型配置；
- 令牌密钥由服务端生成，创建响应中的 `token_key` 只出现一次，响应头禁止缓存，日志和埋点不得记录该字段。

创建成功页提供“我已保存”确认操作和“复制”按钮；离开该页、重新加载或再次进入列表后，密钥不再可取回。用户可暂停/恢复未过期 Token，或执行二次确认后撤销；撤销不可恢复。

### 6.5 受限文本模型测试

服务页提供“文本测试”而不是通用聊天客户端。用户选择一个可用模型，输入最多 4,000 个 Unicode 字符的文本，提交后等待单次非流式响应；首期不保存服务端会话历史，不接受文件、图片、音频、工具调用、函数调用、system/developer prompt、温度、max_tokens 或其他自由参数。

BFF 固定安全请求参数，并将请求转换到既有 Relay 的标准入口。它必须执行现有请求校验、模型渠道分发、频率控制、计费预估、预扣费、结算/退款和消费日志，不能自建余额或直接向上游发送请求。上游响应最长等待 60 秒；超时、模型不可用、额度不足和上游失败以稳定错误码返回，客户端不显示原始上游请求、响应头、渠道名或密钥。

功能由服务端 `MiniProgramTextTestEnabled` 开关和显式模型白名单控制，默认关闭。推荐默认限流为每用户 6 次/分钟、每用户 30 次/日；实际值由管理员在服务端配置，小程序不得传入或覆盖。

## 7. Mini BFF 接口契约

所有响应使用现有统一的成功/错误包络、请求 ID 和 i18n 错误机制。除登录端点外，所有请求要求 `Authorization: Bearer <miniapp-access-token>`；`middleware.MiniAppAuth` 在现有会话认证后额外要求会话 `login_method=wechat-miniapp`，因此浏览器会话和 PAT 不能调用 Mini BFF。

| 方法与路径 | 用途 | 关键约束 |
| --- | --- | --- |
| `POST /auth/wechat` | 微信登录/发现身份状态 | 只收一次性 code；服务端 code2Session |
| `POST /auth/register` | 由已验证微信身份创建账号 | 仅注册开关开启时可用；不接收角色/额度/组 |
| `POST /bindings` | 创建已有账号绑定流程 | 5 分钟、一次性、同源 Web URL |
| `GET /bindings/:id` | 查询绑定结果 | 仅发起该绑定的小程序会话可读取 |
| `POST /auth/renew` | 用新微信 code 续发 access token | OpenID 必须与现有会话一致；不使用 refresh cookie |
| `POST /auth/logout` | 撤销当前小程序会话 | 幂等；清除客户端令牌 |
| `GET /me/overview` | 首页资产摘要 | 不返回管理员字段或原始 Token |
| `GET /plans`、`GET /products`、`GET /orders` | 套餐、商品与本人订单 | 只读、按用户过滤；支付 URL 仅同源白名单 |
| `GET /tokens` | 小程序 Token 列表 | 强制 `source=miniapp`，Key 脱敏 |
| `POST /tokens` | 创建受限 Token | 服务端固定权限与有效期集合；完整 Key 只在此响应出现 |
| `PATCH /tokens/:id/status` | 暂停或恢复 Token | 仅本人且 `source=miniapp` |
| `DELETE /tokens/:id` | 撤销 Token | 仅本人且 `source=miniapp`；不可恢复 |
| `GET /text-test/models` | 当前用户可测试的模型 | 用户可用模型 ∩ 小程序白名单 ∩ 可用渠道 |
| `POST /text-tests` | 发起单次文本测试 | 固定参数、限长、限流、走既有 Relay/计费 |

通用现有端点（包括 `/v1/*`、`/api/token/:id/key`、管理员 `/api/user/*`、渠道管理和全局配置）不得被小程序调用或作为 BFF 透传目标。

## 8. 数据与后端改造

### 8.1 新增数据模型

`WechatMiniIdentity`：

| 字段 | 说明 |
| --- | --- |
| `id` | 主键，由 GORM 生成 |
| `app_id` | 小程序 AppID |
| `open_id` | 微信在该 AppID 下的唯一用户标识 |
| `union_id` | 可选；仅在微信返回时保存，不作为首期绑定前提 |
| `user_id` | The One 用户 ID |
| `created_at`、`last_login_at` | 创建和最后成功登录时间 |

数据库必须对 `(app_id, open_id)` 建唯一索引，对 `user_id` 建普通索引。OpenID 和 UnionID 不出现在访问日志、前端埋点和响应体中。所有迁移用 GORM 和现有跨数据库迁移模式实现，兼容 SQLite、MySQL 5.7.8+ 与 PostgreSQL 9.6+。

`Token` 新增 `source` 文本字段：新小程序 Token 写入 `miniapp`；历史 Token 保持空值或既有来源，不进行破坏性回填。小程序查询和写操作必须显式过滤该值。该字段不是安全边界的唯一保障，所有操作仍须附带 `user_id` 条件。

### 8.2 服务边界

- `router/miniapp-router.go`：注册 `/api/miniapp/v1`，统一路由标签、严格 CORS/域名策略、独立的匿名登录与已登录速率限制。
- `middleware.MiniAppAuth`：复用现有 Bearer 会话验证，并强制 `login_method=wechat-miniapp`；不接受 PAT 或普通 Web 会话。
- `controller/miniapp_*`：只做请求解析、状态码和 DTO 输出，不嵌入账户、Token 或 Relay 业务。
- `service/miniapp_*`：承载微信 code 交换、绑定流程、会话续发、首页聚合、Token 策略和文本测试编排。
- `model/wechat_mini_identity.go`：身份映射及原子绑定查询；锁定更新使用 `lockForUpdate(tx)`。
- 文本测试复用现有 Relay/账单服务，不复制预扣费、结算、模型分发或消费日志逻辑。

微信 AppID 与 AppSecret 必须以服务器端受保护配置提供；AppSecret 不进入数据库响应、前端构建产物、日志或错误信息。小程序上线前在微信后台配置 request 合法域名及 HTTPS 证书。

## 9. 安全、风控与合规要求

1. 所有 JSON 编解码遵循项目 `common` JSON 包装函数；所有用户输入做长度、枚举、归属和权限校验。
2. 认证 code、OpenID、UnionID、session_key、access token、完整 API Key、上游 Key、支付参数不得记录到应用日志、审计 `other`、分析事件或错误消息。
3. 登录、续发、绑定、Token 创建/状态变更/撤销、文本测试均使用独立保守限流；绑定和 Token 写操作需额外 Critical Rate Limit。
4. 文本测试在 Relay 前执行用户状态、模型可用性和额度检查；计费发生异常、配额钳位或预扣费失败时，按现有链路拒绝或记录，不得产生负数扣费或绕过结算。
5. BFF 的 Web URL 只允许站点配置的 HTTPS 同源域名和指定路径；禁止接受客户端传入的 redirect URL，防止开放重定向和令牌泄露。
6. 所有新增消费日志保留请求关联 ID、用户 ID、模型和计费结果；仅管理员可见的元数据记录 `client=miniapp` 与文本测试模式，不记录提示词全文或凭证。
7. 小程序发布前由运营确认主体、类目、隐私政策、生成式 AI 内容治理、实名/备案、日志留存和支付责任满足实际运营地与微信平台要求。本 PRD 不替代法律或平台审核结论。

## 10. 错误处理与体验

| 场景 | 客户端表现 | 服务端行为 |
| --- | --- | --- |
| 微信 code 无效/过期 | 提示“登录已失效，请重试”并自动重试一次 | 不创建会话；记录脱敏失败原因 |
| 注册已关闭 | 显示“请绑定已有账号” | 不创建用户 |
| 身份已绑定他人 | 显示不可继续的安全提示 | 返回固定错误码；不暴露目标账号 |
| 绑定过期/已消费 | 提供重新发起绑定 | 原子拒绝复用 |
| access token 过期 | 静默调用 wx.login 续发；失败则回登录页 | 验证 OpenID 与会话对应关系 |
| Token 超限或模型不可用 | 表单内显示可操作提示 | 不生成 Key、不写部分数据 |
| Token 撤销 | 二次确认后返回列表 | 幂等撤销，后续调用立即无效 |
| 额度不足/文本测试限流 | 显示额度或稍后再试入口 | 在 Relay 前拒绝，不请求上游 |
| 上游超时/失败 | 显示通用失败与重试按钮 | 返回稳定错误码，保留请求关联 ID |
| Web 支付页不可用 | 显示复制链接/稍后重试 | 不创建支付订单，不跳转任意外域 |

## 11. 非目标

- 不把渠道管理、用户管理、全局设置、价格/比率管理、审计后台、权限编辑器搬入小程序。
- 不展示、导出、修改或重新查看用户既有 Web Token；不暴露 `/api/token/:id/key`。
- 不在首期接入微信支付、退款、支付回调、客服、发票、物流或订单履约。
- 不支持图片/音频/视频生成、文件上传、Agent、MCP、长会话、流式输出或异步任务管理。
- 不用 web-view 包装整个现有 Web 控制台；Web-view 仅用于站点同源的绑定/支付页面。
- 不支持小程序端管理员角色提升或多账号合并。

## 12. 分期与发布门槛

### 阶段 0：基础设施与认证

完成 `miniapp/` 空工程、BFF 路由、HTTPS/合法域名配置、微信 code2Session、身份表、创建/绑定/续发/退出与审计。通过未绑定、已绑定、禁用用户、过期 code、重复绑定、会话撤销的回归测试。

### 阶段 1：账户服务

完成首页资产摘要、套餐/商品/订单只读页、同源 Web 绑定/支付跳转和错误态。通过移动设备人工验收与跨数据库迁移测试。

### 阶段 2：Token 与文本测试

完成 Token source 隔离、一次性密钥展示、状态变更/撤销、模型白名单、非流式文本测试和完整计费回归。Token 明文泄露、遗留 Token 越权、模型越权和计费旁路测试必须为零。

### 上线准入

1. 微信开发工具真机测试覆盖 iOS 与 Android 主流版本。
2. BFF 接口、数据库迁移、Relay 账单、Token 所有权和会话撤销的自动化测试通过。
3. 安全审查确认日志脱敏、Token 一次性展示、Web URL 白名单、限流和管理员隔离。
4. 运营确认小程序类目、隐私政策、服务条款、内容治理和平台审核材料。
5. 灰度开关 `MiniProgramEnabled` 与 `MiniProgramTextTestEnabled` 均默认关闭，可独立回滚而不影响现有 Web/API 用户。

## 13. 验收标准

1. 已绑定用户可打开小程序、自动获得有效会话并在首页看到仅属于自己的额度、套餐、用量和订单摘要。
2. 未绑定用户可在注册开启时创建普通账号；注册关闭时只能走已有账号绑定，且绑定不会绕过 2FA/Passkey/OAuth 等既有安全流程。
3. 同一 `(app_id, open_id)` 无法绑定到两个用户；重复、过期或已消费的绑定流程均不会改变账户关系。
4. 小程序无法读取、修改或撤销任何非 `source=miniapp` 的 Token，也无法再次取得已创建 Token 的完整密钥。
5. 小程序创建的 Token 仅允许当前用户可用的分组/模型，带固定到期时间并可由用户暂停、恢复或撤销。
6. 文本测试只接受允许长度的纯文本和用户有权使用的模型；其消耗与现有 Relay 请求一样出现在额度和消费日志中。
7. 额度不足、模型无可用渠道、限流、上游超时均不产生错误扣费，不泄露渠道/上游/凭证信息。
8. 购买入口只打开经服务端校验的同源 Web 页面；小程序不调用支付 API、不创建支付回调。
9. SQLite、MySQL、PostgreSQL 下均能创建身份映射和小程序 Token，并保持唯一性、所有权和锁定语义。
10. 关闭任一灰度开关后，小程序相关能力被拒绝，现有 Web、API 和管理员后台功能不受影响。

## 14. 测试策略

- **模型与服务测试：** 身份唯一性、绑定流程一次性消费、会话 OpenID 校验、Token source/用户双重过滤、Token 输入校验、模型求交和 Web URL 白名单。
- **控制器测试：** 登录、续发、绑定、禁用用户、错误码、访问令牌缺失/过期、一次性 Key 响应禁缓存、所有 BFF 路由的角色隔离。
- **Relay/账单回归：** 文本测试请求在额度足够、额度不足、上游失败、结算差额和配额钳位场景下遵循既有安全不变量。
- **迁移测试：** 在三种数据库上执行新增表/索引/Token 字段迁移，保留已有 Token 可用且不出现在小程序列表中。
- **前端测试：** 登录状态机、绑定轮询、Token 密钥离页隐藏、Token 撤销二次确认、文本输入长度、错误页、Web 支付跳转和所有文案 i18n。
- **人工验收：** 真机检查微信登录、微信返回前台/后台、网络中断恢复、会话撤销、低额度、文本超时及 Web 跳转。
